# Contact module Firestore review

- Target: Standard edition, native mode, default database in `agrodata-ad547`.
- Collection: `contactMessages/{autoId}`.
- Public operation: create only.
- Admin operations: ordered list by `createdAt`, update `status` only, delete.
- Fields: `fullName`, `email`, `phone`, `topic`, `subject`, `message`,
  `status`, `createdAt`.
- PII: names, email addresses, phone numbers, and messages are never publicly
  readable. Reads require the existing `admins/{uid}` role check.
- Create validation: exact schema, bounded strings, topic/status enums, valid
  email, and server timestamp equal to `request.time`.
- Update validation: admin only, complete validator applied, and only `status`
  may change.

## Adversarial checks

- Public list/get: denied because reads require `isAdmin()`.
- Oversized or wrong-type values: denied by the domain validator.
- Missing/extra fields: denied by `hasAll` plus `hasOnly`.
- Timestamp manipulation: denied by `createdAt == request.time`.
- Public update/delete: denied.
- Admin update bypass: validator still runs and the diff permits only `status`.
- Privilege escalation: authority comes from the locked `admins/{uid}` record,
  not request data.
- Query compatibility: admin `orderBy("createdAt", "desc")` is allowed because
  all returned documents satisfy the admin-only read rule.
