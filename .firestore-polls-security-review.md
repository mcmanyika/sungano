# Polls Firestore security review

- Target: Standard edition, native mode, default database (`agrodata-ad547`).
- Collection: `polls/{pollId}`.
- Public operations: read published polls; update vote counts only via
  `isPollVoteUpdate()`.
- Admin operations: create, update, delete, list all (including drafts).
- Fields: `question`, `options` (`[{id,label}]`, 2–6, ids `o0`–`o5`),
  `votes` (map optionId → int), `totalVotes`, `published`, `createdAt`,
  `updatedAt`.
- Vote enforcement: published only; only `votes` + `totalVotes` change;
  `totalVotes` increases by exactly 1; exactly one of `o0`–`o5` increases by 1.
- Client UX stores `sungano-poll-voted:{pollId}` in localStorage (not a
  security boundary).

## Adversarial checks

- Public list of drafts: denied (`published == true || isAdmin()`).
- Public create/delete: denied.
- Oversized question/labels: denied by `isValidPoll`.
- Wrong option ids: denied by option validators.
- Vote inflation (+N on one option): denied (must be +1).
- Voting while changing question/options: denied (`affectedKeys` only votes/totalVotes).
- Voting on unpublished poll: denied.
- Admin update bypass: admin path still requires `isValidPoll`.
- Privilege escalation: authority from locked `admins/{uid}`, not request data.
- Query compatibility: public `where("published","==",true)` and admin
  `orderBy("createdAt","desc")` allowed under the read rules above.
